# 起動時最小化と初回表示の検証

## 報告された症状と修正

macOS で「最小化した状態で起動」がオンのときだけ、背景だけのウィンドウが残る。
赤×で隠して再表示すると UI が描画される。オフでは正常（ユーザー確認）。

旧実装は `Loaded` で最小化し、`OnOpened` で保存サイズ・最大化状態を復元していた。
修正後は保存サイズ・状態を初回 `Show` 前に復元し、最小化は初回 `OnOpened` の後の
`ApplicationIdle` で一度だけ行う。再表示時にはどちらも繰り返さない。
描画バックエンドとアプリのバージョンは変更していない。

## ローカルで確認した結果

- Windows 10.0.26300 / .NET 10.0.12 / Avalonia 12.1.3。
- ネイティブウィンドウの通常起動、最小化起動、トレイ最小化、保存済み最大化＋最小化の4ケースが成功。
- 全ケースで最小化から復帰し、Hide→Show 後も再最小化されず、変更したサイズを維持。
- 保存座標が初回の中央配置で上書きされないことを確認（最大化ケース以外では実座標も照合）。
- 実際の AXAML の文字・レイアウトを確認し、各ケースのビジュアルツリー描画を PNG に保存。
- `dotnet build Ferry.slnx` は警告・エラー0、既存テストは455件成功。

観測値は [result.json](result.json)。再現可能な検証コードと実行コマンドは
[Ferry.StartupSmoke](../../../tests/Ferry.StartupSmoke/README.md) にある。
画像は Avalonia のビジュアルツリー描画であり、OS 合成結果のスクリーンショットではない。

## 未検証と macOS での確認手順

macOS 実機はこの作業環境にないため、元の空白表示の解消と Dock 最小化の実測は未検証。
ネイティブの表示・最小化処理の競合が原因という見立ては、症状・コードに基づく仮説。

1. macOS で検証コードを実行し、4ケースが成功することを確認する。
2. 修正を含む Ferry を起動し、「最小化した状態で起動」をオンにしてメニューの「終了」から終了する。
3. 起動し直し、空白ウィンドウが残らず Dock へ最小化されることを確認する。
4. Dock から復帰し、宛先・設定などの UI が表示されることを確認する。
5. 赤×で隠して再表示しても、再び最小化されないことを確認する。
6. 設定をオフにして終了・起動し、通常表示されることを確認する。
